# CadKit

Use the consumer's existing project, commands and configured runtime. Read its
local workflow guide when resolving paths or conventions; setup is not a routine
prerequisite. An explicit development-source configuration takes precedence over
an older trial receipt. Keep frozen releases unchanged.

For spatial questions and design reviews, prefer showing findings on the model
with attached notes, measurements and useful views. Chat can summarise decisions.
This is a preference, not a tool quota; use other analysis or artifacts when they
better answer the task. Discussing a possible edit does not authorise implementing it.

Read the module needed for the task; combine them when the work crosses boundaries:

| Task | Reference |
| --- | --- |
| Inspect selection, explain fit, review an edit in the app | [Shared review](references/interaction.md) |
| Create or edit geometry, parameters and assemblies | [Modelling](references/agent-guide.md) |
| Declare or validate joints, contact and hardware | [Mechanics](references/mechanics.md) |
| Export, render or slice | [Fabrication and rendering](references/workflows.md) |
| Install or change the runtime | [Setup](references/install.md) |
| Adopt an existing CadQuery project | [Adoption](references/migration.md) |
| MCP, app connection or build failure | [Recovery](references/recovery.md) |

A failed connection is an error to remedy, not a completed review. Try the
applicable recovery; if user action is necessary, provide exact instructions
and identify what remains unverified.
